# Internationalisation (i18n)

The store must be fully usable in English (EN-US) and European Portuguese (pt-PT).
Stories: **US-046** (language selection), **US-047** (all text in the chosen language).

> **Status:** US-046 provides language selection, persistence and propagation, plus
> translated navigation labels. Most interface text is still English only until **US-047**
> translates it, so choosing PT does **not** yet show the whole store in Portuguese.

## Languages

Defined once in `LOCALES` (`app/lib/i18n.ts`):

| Code (cookie, form) | Storefront `LanguageCode` | BCP 47 tag (`<html lang>`, `Intl`) | Name |
| --- | --- | --- | --- |
| `en` (default) | `EN` | `en-US` | English (US) |
| `pt` | `PT_PT` | `pt-PT` | Português (Portugal) |

The country sent to Shopify is always `DEFAULT_COUNTRY` (`US`), whatever the language, so
**changing language never changes market, currency, cart or checkout**. The store
currently has a single market, Portugal (EUR), and Shopify resolves `country: US` to it
(verified with a Storefront API query on 2026-11-11).

The previous subdomain detection (`es.`/`fr.`/`de.`/`jp.` → ES/FR/DE/JA, which also changed
the country) was removed in US-046. Nothing else depended on it apart from its unit tests.

## How the active language is chosen

```
POST /locale  (locale=pt, redirectTo=/current/path?query)
  └─ validates locale (isLocaleCode) and redirectTo (toSafeRedirectPath, same-origin only)
  └─ 302 → redirectTo, Set-Cookie: jeweliette_locale=pt; Path=/; Max-Age=31536000;
                                   HttpOnly; SameSite=Lax; Secure (HTTPS only)
next request
  └─ server.ts → createHydrogenRouterContext → getLocaleFromRequest(request)
       └─ readLocaleCookie(): missing/unsupported value → 'en'
       └─ i18n = {language: 'PT_PT', country: 'US'}
            → context.storefront.i18n, context.customerAccount.i18n
  └─ root loader returns locale = toAppLocale(storefront.i18n) = {code, language, country, tag}
  └─ <html lang={locale.tag}>
```

- `app/routes/locale.tsx` is the only way to change the language. It accepts POST only
  (GET → 405 `Allow: POST`). An unsupported `locale` → 400 and no cookie. An invalid,
  absolute or protocol-relative `redirectTo` → redirect to `/` (no open redirects).
- `server.ts` **appends** the session `Set-Cookie` header rather than replacing it, so the
  language cookie survives when the session is also committed on the same response.
- No page response is publicly cached, and Storefront subrequest cache keys include the
  query variables, so cached Shopify data is per language.

## Reading the language in code

| Where | How |
| --- | --- |
| Loaders and actions | `context.storefront.i18n` / `context.customerAccount.i18n` (`{language, country}`) |
| Components | `useLocale()` → `{code, language, country, tag}` from the root loader. It falls back to English outside the root loader, e.g. on the error page. |
| UI text | `const t = useTranslation(); t('nav.search')`; values: `t('nav.openCart', {count})` |
| Outside React | `createTranslator(code)` |
| Number/date formatting | `Intl.*` with `useLocale().tag` (to be applied across the UI by US-047) |

## UI messages

- Messages live in `app/lib/i18n.ts`. The `en` object defines the key set (`MessageKey`),
  and every other language is typed `Record<MessageKey, string>`, so **a missing or extra
  key fails `npm run typecheck`**. At runtime a missing key falls back to English.
- Placeholders use `{name}` and are filled from the values object. Unknown placeholders are
  left as they are.
- US-046 contains only the keys for the language selector and shared navigation (`language.*`,
  `nav.*`). US-047 extends the same dictionary; if it grows large, split it into one file
  per language under `app/lib/` and keep the API (`useTranslation`, `createTranslator`).

### Adding a string

1. Add the key and English text to `en` in `app/lib/i18n.ts` (group keys with a prefix
   such as `cart.` or `product.`).
2. Add the pt-PT text under `pt`. `npm run typecheck` fails until you do.
3. Use it with `t('your.key')` in components, or `createTranslator(code)` elsewhere.
4. Do not concatenate translated fragments; use one message with placeholders.

## How the language reaches Shopify

- Storefront documents declare `$language`/`$country` and use
  `@inContext(language: $language, country: $country)`.
- Hydrogen's storefront client fills `$language`/`$country` from `context.storefront.i18n`
  when the caller does **not** pass them (verified in the Hydrogen dist code). **Do not pass
  `language` explicitly.**
- Still to fix: `language: 'EN'` is hardcoded 8 times in 7 files (`_index.tsx`,
  `collections.$handle.tsx`, `collections.all.tsx`, `collections._index.tsx`,
  `products.$handle.tsx` ×2, `lib/products.server.ts`, `lib/recommendation/catalog.server.ts`).
- Customer Account documents use `@inContext(language: $language)`, and the account routes
  pass `customerAccount.i18n.language`.
- Customer Account login: Hydrogen sends the context language as the `locale` parameter
  (`PT_PT` → `pt-PT`) unless `?locale=` overrides it (`account_.login.tsx`). This was checked
  in the Hydrogen source, not end to end.

## Formatting

- Money uses Hydrogen's `<Money>`. Its locale handling was not checked (**unverified**).
- Dates still use fixed locales: `Intl.DateTimeFormat('en-US')` on blog pages and
  `toLocaleDateString('en-GB')` on the orders page. To be changed in US-047.

## Shopify content translations

- Products, collections, menus, pages, policies and blogs are translated in the Shopify
  admin (Translate & Adapt, or another translation app), not in this repository.
- **Current store state (Storefront API, 2026-11-11):** the only published language is
  English (`EN`, the default). Portuguese is **not published**, so Shopify answers
  `@inContext(language: PT_PT)` with English content. Portuguese (Portugal) must be added
  and published in the admin, and content translated, before any PT content appears.
- When a resource has no translation for a published language, Shopify documents that the
  default-language text is returned. This could not be verified here because PT is not
  published (**unverified**; US-047 must verify it with a product without a PT description).
- `redirectIfHandleIsLocalized()` (`app/lib/redirect.ts`) redirects to the localized handle
  when the Storefront API returns a translated handle. Products, collections, pages, blogs
  and articles call it.
