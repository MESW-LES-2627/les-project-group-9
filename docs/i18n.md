# Internationalisation (i18n)

The store must be fully usable in English (EN-US) and European Portuguese (pt-PT).
Stories: **US-046** (language selection), **US-047** (all text in the chosen language).

> **Status:** this page describes the code as it is on `main` today, and what US-046 and
> US-047 will add. The "Planned" sections are a design, not existing behaviour. Update this
> page in the same commit as each i18n change.

## Current behaviour (verified in code)

### Locale detection

`getLocaleFromRequest()` in `app/lib/i18n.ts` returns Hydrogen's `I18nBase`
(`{language, country}`). `app/lib/context.ts` passes the result to `createHydrogenContext` as
`i18n`, which makes it available as `context.storefront.i18n` and `context.customerAccount.i18n`.

| Request host | Locale |
| --- | --- |
| `es.<domain>` | `ES` / `ES` |
| `fr.<domain>` | `FR` / `FR` |
| `de.<domain>` | `DE` / `DE` |
| `jp.<domain>` | `JA` / `JP` |
| anything else (incl. `localhost`) | `EN` / `US` (default) |

- There is no language selector, no cookie and no PT support.
- `<html lang="en">` is hardcoded in `app/root.tsx`.
- `tests/unit/i18n.test.ts` covers the subdomain mapping.

### How the language reaches Shopify

- Storefront documents declare `$language`/`$country` and use
  `@inContext(language: $language, country: $country)`.
- Hydrogen's storefront client fills `$language`/`$country` from `context.storefront.i18n`
  when the caller does **not** pass them (verified in the Hydrogen dist code).
- Callers that pass `language: 'EN'` explicitly override the active locale. That happens
  7 times in 6 files: `lib/products.server.ts`, `lib/recommendation/catalog.server.ts`,
  `routes/collections.$handle.tsx`, `collections.all.tsx`, `collections._index.tsx` and
  `products.$handle.tsx` (×2).
- Customer Account documents use `@inContext(language: $language)`, and the account routes
  pass `customerAccount.i18n.language`.
- `account_.login.tsx` forwards an optional `?locale=` parameter and the storefront country
  to `customerAccount.login()`.

### UI strings and formatting

- All UI strings are hardcoded English in JSX, `meta` functions and `app/lib/` (e.g.
  recommendation reasons, preference labels). There is no translation dictionary.
- Money uses Hydrogen's `<Money>`. Its locale handling was not checked (**unverified**).
- Dates use fixed locales: `Intl.DateTimeFormat('en-US')` on blog pages and
  `toLocaleDateString('en-GB')` on the orders page.

## Planned design

### US-046: selection, persistence, propagation

- Supported languages: `EN` (BCP 47 `en-US`) and `PT` (`pt-PT`); default `EN`.
  The ES/FR/DE/JA subdomain mapping is to be removed. US-046 will first list what depends
  on it, and the change needs approval.
- The choice is stored in a cookie: HTTP-only, `SameSite=Lax`, `Secure` on HTTPS, one year.
  `getLocaleFromRequest()` reads it.
- A POST-only route validates the language and a same-origin return path, sets the cookie
  and redirects back (no open redirects).
- The root loader exposes `{language, country, tag}`, and `<html lang>` uses `tag`.
- The country/market does not change with the language, so currency stays the same.
- There is a selector in the header, keyboard accessible, with 44px targets.
- No hardcoded `language` variables remain; `context.storefront.i18n` supplies them.

### US-047: translated text

- A typed dictionary per language in the existing i18n module. Missing keys fail at compile
  time, and English is the fallback.
- Server and client code read the active language from root loader data via a hook.
- Numbers, dates and currency are formatted with `Intl` and the active locale.
- No runtime machine translation, regex or DOM rewriting.

How to add a string will be documented here when the dictionary exists.

## Shopify content translations

- Products, collections, menus, pages, policies and blogs are translated in the Shopify
  admin (Translate & Adapt, or another translation app), not in this repository.
- PT must be enabled as a published language for the storefront in the admin before the
  Storefront API returns PT content (**unverified** for this store).
- When a resource has no translation for the requested language, the Storefront API returns
  the shop's default-language text. This is Shopify's documented behaviour; it has not yet
  been verified against this store (**unverified**).
- `redirectIfHandleIsLocalized()` (`app/lib/redirect.ts`) redirects to the localized handle
  when the Storefront API returns a translated handle. Products, collections, pages, blogs
  and articles call it.
